# Working Style Rules

## Speed over exhaustiveness
- Do the minimum needed to complete the exact task requested. Nothing more.
- After finishing, STOP and report back. Do not proactively fix unrelated issues, refactor, or "improve" other code.
- Do not create additional scratch files, story files, or example scripts unless I explicitly ask for them.

## Testing
- Do not write new test files or test suites unless I ask for tests.
- If existing tests are present, run only the relevant ones for the change you made — not the full suite — unless told otherwise.
- Do not create sandbox/demo scripts to "prove" the code works. Just make the change and describe how I can verify it myself.

## Communication
- After each task, give a short summary (3-5 bullet points max): what changed, which files, and any risks.
- If you hit ambiguity, ask me a direct question instead of guessing and building extra scaffolding to hedge.
- Do not narrate your internal reasoning process at length — just show the result and a brief rationale.

## Iteration loop
- Treat every response as one turn: make the change, stop, wait for my feedback.
- Do not chain multiple rounds of self-review, self-testing, or self-correction in a single turn without me responding in between.
- If a task is large, break it into steps and ask before starting the next step.
